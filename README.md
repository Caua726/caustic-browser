**A web browser written in [Caustic](https://github.com/Caua726/Caustic). Milestone 1.**

> **Read this first.** The whole path from an address to pixels is written and runs:
> network, HTML tree, CSS, cascade, layout, images, painting, navigation and using a page.
> It has been looked at on a handful of pages by hand, so expect it to be wrong on many
> others. The automated evidence is thin: the tokeniser passed the whole html5lib suite,
> before its latest changes, and `--check` drives the tabs. There will be no JavaScript.

## What M2 has

Everything between a URL and the display list, in the order a page goes through it:

```
src/loader/net.cst         bytes for a URL: http and https through caustic-net, file:, data:
src/loader/url.cst         one URL relative to another
src/loader/image.cst       encoded bytes into RGBA, through caustic-image
src/html/tree.cst          the WHATWG tree builder, scripting off
src/dom/                   the tree, its tags, and --dump-dom
src/css/tokens.cst         CSS Syntax's tokenizer
src/css/sheet.cst          rules, selectors and @media, @supports, @import
src/css/decl.cst           one declaration into longhands: shorthands, calc(), colours
src/css/props.cst          every longhand, generated by tools/gen_props.py
src/css/ua.cst             the browser's own stylesheet
src/css/style.cst          the cascade, var(), HTML's old attributes, computed values
src/css/transform.cst      a transform's functions as a matrix, and what lies between two
src/css/dump.cst           --dump-css
src/layout/box.cst         the box tree's types
src/layout/build.cst       boxes from the DOM, and every anonymous box CSS asks for
src/layout/flow.cst        blocks, margin collapsing, floats and lines
src/layout/table.cst       tables, the automatic and the fixed algorithm
src/layout/flex.cst        flexbox
src/layout/grid.cst        grid: placement and track sizing
src/layout/layout.cst      position, and where everything ended up
src/layout/measure.cst     how wide text is, asked of the window
src/paint/paint.cst        boxes into a display list, in CSS's painting order
src/paint/pixels.cst       gradients and uneven rounded borders, as pixels
src/paint/svg.cst          inline <svg>: shapes, paths, gradients, strokes
src/page/page.cst          one page: load, relayout, what a point leads to, hover and focus
src/page/anim.cst          transitions and @keyframes, written over the style each frame
src/page/forms.cst         what controls are, and what using them does to the document
```

What it leaves out, knowingly: `filter` and `backdrop-filter`, `inset` shadows, animating
anything that moves other boxes (width, margins, `box-shadow` and such change at once),
more than one animation on an element, a calendar for `type=date` and a colour picker
for `type=color`, SVG's `<text>`, clips, masks and patterns, sending forms by POST,
justified text, encodings other than UTF-8, `<select multiple>` (it behaves as a single
choice) and choosing a file for `type=file`. A clip's rounded edge is not anti-aliased.
Loading blocks the window, and resources are fetched one at a time.

`browser ADDRESS` opens a page, as a URL or a path, and so does the address bar. Links
are followed, Ctrl+click or the middle button open a new tab, and Alt+Left, Alt+Right,
Ctrl+R and F5 do what they do elsewhere.

A page answers to the pointer and the keyboard: `:hover`, `:active`, `:focus`,
`:focus-visible`, `:focus-within`, `:target` and `cursor`; selecting text and copying it
(a double click a word, a triple click a line, Ctrl+A); the right-click menu; the wheel
inside a box that scrolls; `<details>`; labels; checkboxes and radio buttons; `<select>`,
by its menu or the arrow keys; `range` by dragging or the arrow keys; `date` typed as
dd/mm/yyyy; Tab through what takes the focus; and forms submitted by
GET, or put back by a reset. A field being typed in is the toolkit's entry or text view
held over the box, which is why its text takes the toolkit's font until it loses the focus.

`caustic-net` is not pinned in the Causticfile because its only tag predates `fetch`.

What moves does not lay anything out again: each frame writes its values over the computed
style and paints the list again, and only the area it changed is repainted. With a software
renderer a page that keeps animating still costs about a third of a core.

## What M0 establishes

The window, on the toolkit of
[`caustic-media`](https://github.com/Caua726/caustic-media): a dark two-row header,
tabs as plain text beside the window's own buttons, and a white page. The shortcuts
are `Ctrl+T`, `Ctrl+W`, `Ctrl+L`, `Ctrl+Q`, and `Ctrl+Tab` or `Ctrl+Page Down` to move
between tabs. Tabs past the room scroll sideways.

The page area is a widget of our own, and it plays back a **display list**. That
list is the boundary that matters for what comes next: the engine ends there and never
touches the toolkit, so layout and paint can be tested by comparing lists, with no
window and nothing linked. Text and shapes on the other side of it come from
`caustic-media`'s `text/` and `render/`.

```
src/main.cst               starts the program, drives it with --check, or prints
                           what it read with --dump-dom and --dump-css
src/ui/browser.cst         the window: tabs, toolbar, address, shortcuts
src/ui/chrome.cst          what the toolkit has no widget for: the tabs, drawn icons
src/ui/theme.cst           the palette and the sizes
src/ui/page_view.cst       the page's widget: plays a display list back
src/paint/display_list.cst what a page draws, as data
src/paint/placeholder.cst  what a tab shows before it has gone anywhere
tests/test_paint.cst       the display list, without a window
```

## What M1 establishes

**The HTML tokeniser, WHATWG §13.2.5 — all of it.** 7032 of 7032 cases in the
[html5lib conformance suite](https://github.com/html5lib/html5lib-tests) pass,
at every optimization level the compiler offers — `-O0`, `-O1` and `-O2` — in
0.1 s each.

The whole state machine rather than the subset that gets `<p>hello</p>` working,
because the subset is what turns into a rewrite the first time a real page
arrives. Three things break a naive tokeniser on the first site anyone tries:

- `<script>if (a<b) {}</script>` — inside a script, `<` is not markup. Worse,
  `<!--` inside a script enters an escaped state where `</` **is** markup again,
  and `<script` inside *that* enters a double-escaped state where it is not.
  Fourteen states exist for this one problem and every one is reachable from a
  page that ships an ad tag.
- `&notin;` and `&not` are both named references and one is a prefix of the
  other. Matching is longest-first over 2231 names — and in an attribute value
  `?a=1&nots=2` must **not** become `?a=1¬s=2`, while outside one the same
  input is the entity.
- `<title>a < b</title>` — RCDATA. `<` is text unless what follows is the end
  tag for *this* element, so the tokeniser has to remember which start tag
  opened the region.

It reads **bytes, not codepoints**. Not a shortcut: every character the machine
branches on is ASCII, and in UTF-8 no byte of a multi-byte sequence is ever
below 0x80, so a byte-oriented scanner takes the same transitions. The two
places it would matter are handled — U+0000 becomes U+FFFD, and numeric
references are encoded to UTF-8.

```
src/html/tokenizer.cst     the state machine
src/html/entities.cst      GENERATED — the 2231 named references
src/html/tree.cst          the tree builder: tokens into a document
src/dom/dom.cst            the document's nodes
src/dom/tags.cst           the tags the parser knows by name, and its lists of them
src/dom/dump.cst           a tree as text
src/loader/file.cst        a whole file in memory
tests/test_tok.cst         the html5lib suite, replayed and compared
tests/vec_tok.cst          GENERATED — 7032 cases, six initial states
tools/gen_entities.py      entities.json    -> src/html/entities.cst
tools/gen_tok_vectors.py   html5lib-tests/  -> tests/vec_tok.cst
```

Both generated files are committed and both generators are committed with them;
regenerating either is one command, documented at the top of the script.

**Parse errors are counted, not itemised.** Each html5lib case lists the errors
it expects and where; this counts them without recording positions, so a case
that should have raised one and did not still passes. That is a real hole rather
than an oversight — closing it means carrying a position with every error, which
the tree builder will want anyway.

## Not built yet

Everything else, in the order it is likely to be needed: the tree builder, a URL
parser and HTTP (from [`caustic-net`](https://github.com/Caua726/caustic-net), which
now does `fetch(url) -> bytes` with TLS), CSS parsing and the cascade, box layout,
and — much later, if ever — a JavaScript engine. Fonts, shaping and image decoding
come from `caustic-media`.

## Building it

Requires a [Caustic toolchain](https://github.com/Caua726/Caustic) built from
source: `caustic-media` does not compile with the v0.1.11 release.
[`caustic-media`](https://github.com/Caua726/caustic-media) is a declared dependency,
cloned into `.caustic/deps` at its pinned tag on the first build. The tokeniser and
paint tests link nothing. The window needs glibc, libX11, libXext, libXi, libXfixes,
libXrandr, libXcursor and libxkbcommon to start, and `test-ui` needs `xvfb-run` and
at least one font.

```sh
caustic-mk run test         # the tokeniser and paint suites, then the window, driven
caustic-mk run test-opt     # the tokeniser suite at -O1 and -O2
caustic-mk build browser && ./build/browser
```
